# プロジェクト相対パス基準管理およびパス処理一元化仕様

## 1. 概要

本仕様書は、`novelaide` におけるファイルパス管理アーキテクチャを「OS絶対パス依存」から「プロジェクトフォルダー基準の相対パス管理」へと刷新し、全ドキュメント・エントリに必要なパス・ファイル名属性を事前格納して各UIコンポーネントでのローカル文字列操作（`split(/[/\\]/)` や正規表現スライス）を撲滅するとともに、フォールバック処理自体の発生を根絶する仕様を定義するものです。

---

## 2. 背景と設計方針

### 2.1 従来の課題
- 従来の `path` には `D:\repos\project\01_第1話.md` という OS 固有の絶対パスが格納されていた。
- そのため、各コンポーネントが「ファイル名」「拡張子」「親フォルダ名」「相対位置」を必要とするたびに、`path.split(/[/\\]/).pop()` や `path.replace(/\.[^/.]+$/, '')` 等の手書きローカル処理を個別に行っていた。
- `fileService.readFile` では、エラー時に自前でパスを解析してダミーやモックをでっち上げるフォールバックが存在し、整合性破壊やバグの温床となっていた。
- 将来的なマルチプロジェクト（複数ワークスペース同時参照）対応を考慮すると、絶対パス単独での管理は結合度が高すぎた。

### 2.2 改善方針
1. **内部管理を「プロジェクトフォルダー基準の相対パス」に移行**:
   - アプリ内部の主キー・識別子・タブ表示には、OS非依存のクリーンな相対パス（例: `"novels/01_第1話.md"`, `".gitignore"`）を使用。
2. **ファイルI/O境界でのみ「絶対パス」を使用**:
   - 実ファイルアクセス用に `absolutePath`（例: `"D:/project/novels/01_第1話.md"`）を事前保持。
3. **マルチワークスペース対応用の「プロジェクトパス」保持**:
   - ドキュメントが所属するプロジェクトのルート絶対パス（`projectPath`）を保持。
4. **全属性の事前格納（ローカル文字列操作の撲滅）**:
   - `baseName`, `fileTitle`, `extension`, `relativeParentDir`, `parentDir` をバックエンド（Rust `std::path::Path`）で完全解析して事前格納。各コンポーネントはこれらを直接参照する。
5. **フォールバック処理の完全撤廃**:
   - バックエンドが常に確定した安全な情報を返すため、フロントエンドの無理なパス解析・ダミーでっち上げを完全撤廃。

## 3. データ構造仕様

### 3.1 属性定義一覧

| 属性名 | 型 | 説明 | 具体例 |
| :--- | :--- | :--- | :--- |
| **`relativePath`** | `string` | **プロジェクトルート基準の相対パス（内部管理主キー）** | `"novels/01_第1話.md"`, `".gitignore"` |
| **`absolutePath`** | `string` | **実ファイルの OS 絶対パス（読み書き専用）** | `"D:/project/novels/01_第1話.md"` |
| **`projectPath`** | `string` | **所属プロジェクトのルート絶対パス（マルチWS対応）** | `"D:/project"` |
| **`relativeParentDir`** | `string` | プロジェクト内の相対親ディレクトリ | `"novels"`, `""`（ルート直下） |
| **`parentDir`** | `string` | 実ファイルの絶対親ディレクトリ | `"D:/project/novels"` |
| **`baseName`** | `string` | 拡張子を含むファイル名 | `"01_第1話.md"`, `".gitignore"` |
| **`fileTitle`** | `string` | 拡張子を除いたファイル名（表示・編集用） | `"01_第1話"`, `".gitignore"` |
| **`extension`** | `string` | 小文字の拡張子（ドットなし） | `"md"`, `"gitignore"`, `"json"`, `""` |
| `path` | `string` | 互換用プロパティ（内部的には `relativePath` または `absolutePath` と同期） | |

## 4. `novelaid-fs` パスライブラリ関数の提供

フロントエンドにおいて任意のパス文字列を操作する必要があるケース（エクスプローラーのコンテキストメニュー等）に対しても、手書きの文字列置換を禁止し、`tauri-plugin-novelaid-fs-api` から公式なパス関数を提供します。

- `basename(path: string): string`
- `dirname(path: string): string`
- `extname(path: string): string`
- `stem(path: string): string`
- `join(dir: string, ...segments: string[]): string`
- `normalize(path: string): string`
- `isSubPath(child: string, parent: string): boolean`
