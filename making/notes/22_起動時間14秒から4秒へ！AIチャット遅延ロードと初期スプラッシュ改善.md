# 第22回：起動時間14秒から4秒へ！AIチャット遅延ロードと初期スプラッシュ改善

こんにちは！ 小説執筆用エディター **`novelaide`**（コードネーム: `novelaid-e`）開発チームです。

今回は、開発中に直面した**「アプリの起動が異常に遅く、真っ白な画面が長く続いてしまう問題」**の調査と、劇的な改善（14秒 → 4.6秒）を達成したプロセスをお届けします。

---

## 1. ユーザーからのSOS：「起動が遅すぎる！」

ある日、テスト中に以下のような相談が寄せられました。

> 「現在、アプリを起動してから、実際のアプリの画面になるまで、かなりの時間がかかっています。
> 1. アプリ起動
> 2. 白い画面が表示。ただし固まっているわけではなく、白い初期画面の模様
> 3. エディター画面（ダークテーマ）表示
> 開発者ウィンドウを開いてもエラーは出ていません。状況を確認できるように起動関連部分にログを追加してください。」

デスクトップアプリにおいて、起動してから操作可能になるまでに10秒以上も待たされるのは、作家の「さあ書くぞ」という創作意欲を大きく削いでしまいます。

---

## 2. 起動プロファイラー（`bootLogger`）で原因をミリ秒単位で特定

「どこで時間がかかっているのか」を突き止めるため、ミリ秒精度の起動プロファイルロガー `bootLogger` を導入しました。

```typescript
// src/utils/bootLogger.ts
export const bootTimeStart = typeof performance !== 'undefined' ? performance.now() : Date.now();

export function bootLog(message: string, ...args: any[]): void {
  const elapsed = (performance.now() - bootTimeStart).toFixed(1);
  console.log(`%c[Boot +${elapsed.padStart(7, ' ')}ms]%c ${message}`, 'color: #3b82f6; font-weight: bold;', 'color: inherit;', ...args);
}
```

これを `index.html` のインラインスクリプト、`main.tsx`、`App.tsx`、各プロバイダーに仕込んで計測したところ、衝撃のログが出力されました。

```text
[Boot +   0.0ms] index.html inline script executed
react-dom-client.development.js:31148 Download the React DevTools for a better development experience
[Boot +14076.4ms] main.tsx module loaded, mounting React root...
[Boot +14078.1ms] React root.render() called
```

なんと、**`index.html` が読み込まれてから `main.tsx` のモジュール解決が終わるまでに 14秒（14,076ms）もかかっていた**のです！

---

## 3. ボトルネックの正体：AIエージェントの巨大バンドル（8.2MB）

Vite のビルド出力やモジュール依存関係を詳細に分析したところ、単一のモジュールが異常なサイズになっていることが判明しました。

```text
dist/assets/browser-BS2yt7wv.js       8,188.82 kB │ gzip: 5,991.56 kB
```

正体は、AIチャット機能で採用している `@earendil-works/pi-coding-agent` および `@earendil-works/pi-ai` でした。
ブラウザやWebView環境で自律AIエージェントを動かすため、WebAssembly（Wasm）ランタイム、仮想ファイルシステム（fsポリフィル）、暗号ライブラリ、Go/Wasmランタイムなどが丸ごとバンドルされており、起動時にブラウザエンジンがこれをパース・初期化するのに10秒以上を費やしていたのです。

---

## 4. 解決策：`React.lazy` による遅延ロード化

小説を書くとき、作家が毎回必ずAIチャットを使うとは限りません。
起動時にAIランタイムを読み込む必要はなく、**「作家がAIチャットパネルを開いた瞬間」に初めて読み込めば十分**です。

そこで、`App.tsx` の起動ルートから `AIContextProvider` を外し、AIパネルプラグイン（`AiPanelPlugin.tsx`）の内部で `React.lazy` による動的インポートへ切り替えました。

```typescript
// src/plugins/panels/AiPanelPlugin.tsx
import React, { lazy, Suspense } from 'react';
import { PanelPlugin } from '../types';

// AIチャットの本体コンポーネントを遅延ロード（Lazy Load）
const LazyAIChatPanel = lazy(() => import('../../components/AI/AIChatPanel').then(m => ({ default: m.AIChatPanel })));

export const AiPanelPlugin: PanelPlugin = {
  id: 'panel.ai',
  title: 'AIアシスタント',
  icon: '🤖',
  component: () => (
    <Suspense fallback={<div className="p-4 text-sm text-gray-400">AIランタイムを読み込み中...</div>}>
      <LazyAIChatPanel />
    </Suspense>
  ),
};
```

### 結果：起動時間が 14秒 → 4.6秒に激減！

```text
[Boot +   0.0ms] index.html inline script executed
react-dom-client.development.js:31148 Download the React DevTools for a better development experience
[Boot + 4606.1ms] main.tsx module loaded, mounting React root...
[Boot + 4607.6ms] React root.render() called
```

重いAIバンドルをメインバンドルから完全に切り離したことで、**起動時間が約10秒も短縮**されました！

---

## 5. さらなるUX向上：白画面の解消と「和ませスプラッシュ画面」

起動速度は改善されたものの、ユーザーから「読み込み中に一瞬白い画面が出る」「待っている間、アイコンの犬を表示して場を和ませてほしい」という素敵なアイデアをいただきました。

そこで以下の2つの施策を実施しました。

### ① OSウィンドウの背景色（Dark）指定
Tauriの設定（`tauri.conf.json`）でウィンドウ生成時の背景色をあらかじめエディターのダークカラーに合わせておくことで、OSウィンドウ出現時の「白画面フラッシュ」を完全に防止しました。

```json
// src-tauri/tauri.conf.json
"app": {
  "windows": [
    {
      "title": "novelaide",
      "theme": "Dark",
      "backgroundColor": "#1e1e1e"
    }
  ]
}
```

### ② HTMLインラインの犬スプラッシュ画面
Reactが立ち上がるまでのわずかな読み込み時間中、`index.html` にあらかじめスタイルとアプリアイコン（可愛い犬のアイコン）をインライン配置し、ふんわりと脈打つアニメーションで作家を迎える演出を加えました。

```html
<!-- index.html -->
<div id="root">
  <div class="boot-splash-container">
    <div class="boot-splash-avatar-wrapper">
      <img src="/icon.png" alt="novelaide icon" class="boot-splash-avatar" />
    </div>
    <div class="boot-splash-title">novelaide</div>
    <div class="boot-splash-subtitle">執筆空間を準備中...</div>
  </div>
</div>
```

React のマウントが完了すると、このスプラッシュはエディターのUIに自然に置き換わります。

## 6. まとめと次回予告

* **測定なくして改善なし**: `bootLogger` によるミリ秒単位のプロファイリングにより、真のボトルネック（AIバンドルのサイズ）を一発で突き止めました。
* **関心事の遅延化（Code Splitting）**: 起動時に不要な巨大モジュールは `React.lazy` で分離することで、起動速度とリッチな機能性を両立しました。
* **細やかなUX演出**: ダーク背景の先行指定と親しみやすいスプラッシュ画面により、体感待ち時間を心地よい体験へと変身させました。

次回は、**「執筆を邪魔しない外部ファイル同期と、原稿の消失・誤削除を防ぐ多層的オートセーブの実装」**をお届けします。どうぞお楽しみに！
