# 第51回：Windowsインストーラーを日本語化する！NSIS・WiXの多言語対応とレジストリ安全設計

こんにちは！ 小説執筆用エディター **`novelaide`**（コードネーム: `novelaid-e`）の開発メイキング連載第51回です。

デスクトップアプリを開発し、いざ他のユーザーや作家仲間に使ってもらおうとしたとき、最初に触れる画面はエディターではなく**「インストーラー」**です。
セットアップ画面が英語だったり、不要なレジストリ変更が行われたりすると、ユーザーは不安を感じてしまいます。

今回は、Tauri v2 における Windows 向けインストーラー（NSIS と WiX / MSI）の仕組みを解き明かし、**「完全日本語化」**と**「作家のPCを汚さないレジストリ非侵襲設計」**を両立させた設定の全貌をお届けします！

---

## 1. Tauri v2 の2大インストーラー（NSIS と WiX）

開発者から次のような相談が寄せられました。

```markdown
> インストーラーの調整を行う予定です。
> 特に、日本語対応など。
> まず、Tauriアプリにおける、インストーラー生成の仕様などを詳しい資料にまとめてください。
```

Tauri v2 では、Windows 向けに主に以下の2つのインストーラー形式をサポートしています。

| 形式 | 拡張子 | バンドラー | 特徴 |
| :--- | :--- | :--- | :--- |
| **NSIS** | `setup.exe` | Nullsoft Scriptable Install System | 軽量で高速。単一の exe に多言語リソースを内包できる。個人向け配布に最適。 |
| **WiX** | `.msi` | Windows Installer XML Toolset | Windows 標準のインストーラー形式。企業のグループポリシー配布やサイレント導入に適する。 |

```markdown
> 設定ファイルの変更のみで、実際のWiXのファイルとかは自動生成ですか？
```

Tauri では、WiX の `.wxs` や NSIS の `.nsi` スクリプトを一から手書きする必要はありません。
`src-tauri/tauri.conf.json` の設定をもとに、ビルド時にバックグラウンドで一時ファイルとして完全自動生成される仕組みになっています。

## 2. インストーラーの日本語化とカルチャーサフィックスの謎

日本語化にあたり、開発者から具体的な要件が提示されました。

```markdown
> インストーラーを日本語用に調整する計画を立ててください。
> なお、それ以外の設定は基本的にデフォルトのままで良く、
> ライセンスやファイル関連付けなどの追加設定も不要です。
> 特に、ファイルの関連付けなどレジストリに影響する処理は行わないでください。
> ただし、インストーラー用のアイコンなどはアプリのアイコンと同じにそろえてください。
>
> msiのファイル名が、novelaide_0.48.1_x64_en-US.msiとなっていますが、
> 日本語化した場合、*_ja-JP.msiになるのでしょうか？
```

### WiX（MSI）のファイル名仕様
調査の結果、Tauri の WiX バンドラーは、設定した言語コード（カルチャーコード）を出力ファイル名末尾に `_[Language-Culture].msi` として必ず付与する仕様であることがわかりました。
そのため、`language: "ja-JP"` を指定すると、成果物名は自動的に `novelaide_<version>_x64_ja-JP.msi` となります（カルチャー表記付きで問題なしとの方針で合意）。

### NSIS の多言語仕様
一方、NSIS は1つのバイナリに複数の言語リソースを埋め込むことができます。
`languages: ["Japanese", "English"]` と指定し、`displayLanguageSelector: false` に設定することで、OSが日本語環境であれば言語選択画面をスキップして即座に親切な日本語UIでセットアップが開始されるように最適化しました。

## 3. 作家のPCを汚さない「レジストリ非侵襲」ポリシー

今回の設計において最も重視したのが、**「レジストリに影響を与える処理（ファイル関連付け等）を行わない」**という点です。

```jsonc
// 敢えて設定しない（安全設計）
// "fileAssociations": [ ... ] は一切記述しない！
```

### なぜファイル関連付けを行わないのか？
小説執筆環境では、作家ごとに慣れ親しんだテキストエディターやマークダウンビューアーが存在します。
インストーラーを実行しただけで `.md` や `.txt`、あるいは独自の拡張子が勝手に novelaide に紐づけられ、ダブルクリック時の既定アプリが書き換わってしまうと、既存の執筆フローを妨害してしまいます。

novelaide は、**「必要なときに起動して作品フォルダーを開く」クリーン＆ポータブル志向**を徹底するため、レジストリの拡張子登録は一切行わない方針としました。

## 4. `tauri.conf.json` の最終構成

完成した設定は以下の通り、極めてシンプルかつ堅牢です。

```jsonc
{
  "version": "../package.json", // npm version とインストーラーバージョンを完全自動同期！
  "bundle": {
    "windows": {
      "nsis": {
        "languages": ["Japanese", "English"],
        "displayLanguageSelector": false,
        "installerIcon": "icons/icon.ico" // アプリアイコンと統一
      },
      "wix": {
        "language": "ja-JP"
      }
    }
  }
}
```

### 実機ビルド検証
設定後、ローカル環境で実機ビルドを実行しました。

- **NSIS**: `npm run tauri -- build -b nsis`
  - 成果物: `src-tauri/target/release/bundle/nsis/novelaide_0.54.0_x64-setup.exe` (20.93 MiB)
  - 起動確認: 日本語で「novelaide セットアップへようこそ」が表示され、アイコンも統一。
- **WiX (MSI)**: `npm run tauri -- build -b msi`
  - 成果物: `src-tauri/target/release/bundle/msi/novelaide_0.54.0_x64_ja-JP.msi` (25.02 MiB)

どちらもエラーなく完璧にビルドが成功しました！

## 5. まとめと次回予告

今回は、ユーザーが最初に触れるインストーラーのローカライズと安全設計を実施しました。

* **完全日本語化**: NSIS の日本語リソース内包と WiX の `ja-JP` カルチャー指定。
* **アイコン統一**: セットアップ実行ファイルにもアプリアイコン（`icons/icon.ico`）を適用。
* **レジストリ非侵襲**: ファイル関連付けを行わず、作家の環境を尊重するクリーン設計。
* **バージョン同期**: `"version": "../package.json"` による手作業ミスの根絶。

インストーラーが完成したことで、いよいよアプリを配布できる状態になりました。  
しかし、一度配布したアプリに新機能やバグ修正を提供するにはどうすればよいでしょうか？
毎回手動でインストーラーをダウンロードしてもらうのは不便です。
