## 1. アプリの「顔」としてのアイコンの重要性

デスクトップアプリを起動した時、タスクバーやDock、デスクトップショートカットに表示されるアイコンは、まさに**アプリの顔**です。

開発初期の段階では、ViteやTauriのデフォルトロゴが表示されたままになっていることがよくあります。しかし、一般ユーザーに向けて公開するにあたっては、愛着の持てる固有のアイコンが設定されていることが「安心して使える道具」としての第一歩になります。

先行する `novelaid-editor` では、猫をモチーフにした親しみやすいアプリアイコン（猫モフアイコン）が長らく愛されてきました。今回の `novelaide` でもこのシンボルを正統継承し、現代的なデスクトップ環境にマッチした高解像度アイコンへと整えていきます。

## 3. Tauri 2.x の魔法：`tauri icon` コマンドによる一発自動生成

Windows用の `.ico`（複数の解像度が1つにまとまったファイル）や、macOS用の `.icns`（Retinaディスプレイ対応の高画質アイコン）、さらにはLinux用の各種PNGなど、デスクトップアプリのアイコンは**プラットフォームごとに必要な画像形式やサイズがバラバラ**で、手動で作るのは非常に骨が折れます。

しかし、**Tauri 2.x には標準で最強のアイコン生成コマンド**が用意されています！

### 実行手順

1. **マスター画像の準備**:
   - `assets/1024x1024.png` に、正方形（1024×1024ピクセル）の透過PNG画像を配置します。
2. **コマンドの実行**:
   - ターミナルで以下のコマンドを1行実行するだけです。

```pwsh
npx tauri icon assets/1024x1024.png
```

このコマンドを実行すると、CLIが自動的に画像のリサイズとフォーマット変換を行い、`src-tauri/icons/` 配下にすべてのプラットフォーム用アセットが一瞬で生成されます。

```text
        Appx Creating StoreLogo.png
        Appx Creating Square150x150Logo.png ...
        ICNS Creating icon.icns (macOS用)
         ICO Creating icon.ico (Windows用)
         PNG Creating 32x32.png, 128x128.png, 128x128@2x.png ...
```

手動で画像編集ソフトを使ってサイズごとに書き出したり、オンライン変換サイトを使ったりする必要が一切ありません。

## 4. `public/` の断捨離とファビコンの最適化

開発初期のテンプレートから残っていた不要なファイルも整頓しました。

* **削除したファイル**:
  - `public/tauri.svg`（初期テンプレートのTauriロゴ）
  - `public/vite.svg`（初期テンプレートのViteロゴ）
* **配置したファイル**:
  - `public/icon.png`（新アプリアイコン）
  - `public/favicon.ico`（Web用ファビコン）

そして、`index.html` の `<head>` セクションも以下のように綺麗に書き換えました。

```html
<link rel="icon" type="image/png" href="/icon.png" />
<link rel="alternate icon" href="/favicon.ico" />
```

これにより、開発サーバー起動時やWebブラウザプレビュー時にも、タブにオリジナルのアプリアイコンが美しく表示されるようになりました。

## 5. オープンソースとアセット保護の共存

ここで1点、GitHubでアプリを公開するにあたって非常に大切なポイントがあります。それが**「コードのライセンス」と「ビジュアルアセットの権利」の分離**です。

```text
----------------------------------------------------------------
EXCLUSIONS FROM THE MIT LICENSE (Asset Ownership)
----------------------------------------------------------------
The following assets are NOT included under the MIT License:
1. Application Icons, Logos, and Branding Materials
2. Graphic Assets, Images, and Illustrations
3. Sample Content or Template Files
```

この特記事項を設けることで、
* 「開発者は自由にコードを参考にして自分用アプリを作れる」
* 「アプリ固有のブランドイメージやイラストは保護される」
という両立を実現しています。
