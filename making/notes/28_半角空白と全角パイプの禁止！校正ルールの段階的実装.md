## 1. なぜ小説で「半角空白」と「全角パイプ」を禁止するのか？

日本語の小説原稿では、一般的なビジネス文書やプログラミング用コードとは異なる、独自の組版・出版作法が存在します。

### ① 半角空白（` `）の禁止
* **小説作法**: 日本語の小説では、段落冒頭の「字下げ」や感嘆符・疑問符（！？）直後のアキなど、空白を空ける場面では**すべて全角空白（`　`）を使用する**のが鉄則です。
* **混入の課題**: PCやスマホでの入力時、無意識に半角スペースキーを押してしまったり、Webからのコピペ原稿に半角スペースが混ざっていたりすると、電子書籍リーダーや原稿用紙換算、縦書きプレビューで表示が崩れる原因になります。
* **解決策**: 小説本文中に半角空白（`0x20`）が現れたら即座に指摘し、ワンクリックで全角空白（`　`）へ置換できるようにします。

### ② 全角パイプ（`｜`）の禁止
* **ルビ記法の統一**: カクヨムや青空文庫などの小説投稿サイトや組版エンジンでは、ルビ開始記号として全角 `｜` を許容するものもありますが、本プロジェクト（`novelaide`）では前回の改修によって**半角パイプ `|` に厳格に統一**しました。
* **本文混入の防止**: また、小説の地の文や会話文で縦棒「｜」を記号として使うことは基本的にありません。全角パイプが残っているとルビ表記揺れの原因となるため、見つかり次第、半角 `|` へ直すよう促します。

   - 常用漢字・形式名詞の開き辞書の拡充

   - キャラクター名・地名設定資料からの自動辞書生成と表記揺れ検知

## 3. ルールエンジンのモジュール化（Trait + Registry パターン）

校正ルールが増えていく中で、初期の実装では `desktop.rs` の単一ループ内にすべてのルールがべた書きされていました。
これでは、**「将来設定画面でルールごとのON/OFFを切り替える」「助詞連続の許容回数をユーザーが微調整する」**といった要望に対応できません。

そこで、Rustの **Trait（インターフェース）** と **Registry（登録管理）パターン** を導入し、ルールごとにファイルを完全分離するクリーンアーキテクチャへと刷新しました！

```mermaid
classDiagram
    class CalibrationRule {
        <<trait>>
        +id() &str
        +name() &str
        +rule_type() &str
        +default_enabled() bool
        +check(ctx) Vec~CalibrationIssue~
    }

    class RuleRegistry {
        -rules: Vec~Box~dyn CalibrationRule~~
        +register(rule)
        +check_all(ctx, settings) Vec~CalibrationIssue~
    }

    class ProhibitedCharRule {
        +target_char: char
        +suggestion: Option~String~
        +message: &str
    }

    CalibrationRule <|.. ProhibitedCharRule : 実装
    CalibrationRule <|.. ClosingPeriodRule : 実装
    CalibrationRule <|.. ThreeDotsLeaderRule : 実装
    RuleRegistry o-- CalibrationRule : 動的登録・一括実行
```

### ① 汎用文字禁止ルール `ProhibitedCharRule` による量産化
「指定した文字を禁止し、推奨文字を提案する」というルールは、共通の構造体として抽象化できます。

```rust
// tauri-plugin-novelaid-calibration/src/rules/prohibited_char.rs
pub struct ProhibitedCharRule {
    pub id: &'static str,
    pub name: &'static str,
    pub target_char: char,           // 禁止文字 (例: ' ' や '｜')
    pub suggestion: Option<String>,  // 推奨置換文字列 (例: "　" や "|")
    pub message: &'static str,       // 指摘メッセージ
    pub default_enabled: bool,
}
```

コンストラクタに引数を渡すだけで、「半角空白禁止」も「全角パイプ禁止」もわずか数行で安全に定義できます。

```rust
// 半角空白禁止ルールの生成・登録
registry.register(ProhibitedCharRule::new(
    "novel-no-half-width-space",
    "半角空白の禁止",
    ' ',
    Some("　".into()),
    "小説執筆では原則として半角空白は使用しません。全角空白への置換を推奨します",
));

// 全角パイプ禁止ルールの生成・登録
registry.register(ProhibitedCharRule::new(
    "novel-no-full-width-pipe",
    "全角パイプの禁止",
    '｜',
    Some("|".into()),
    "ルビ開始記号には半角パイプ「|」を使用します。全角「｜」は使用しません",
));
```

### ② ファイル分割と1ルール1責務の徹底
すべてのルールが `src/rules/` ディレクトリ配下に1ファイル1ルールとして独立しました。

* `src/rules/context.rs`: テキスト・行一覧・形態素トークン情報をまとめたコンテキスト
* `src/rules/prohibited_char.rs`: 汎用文字禁止ルール（半角空白・全角パイプ）
* `src/rules/closing_period.rs`: 会話文末の句点ルール（`「〜。」`）
* `src/rules/three_dots_leader.rs`: 三点リーダー2マスルール（`……`）
* `src/rules/exclamation_space.rs`: 感嘆符・疑問符後の全角空白ルール
* `src/rules/doubled_joshi.rs`: 助詞「の」連続ルール（`max_allowed` パラメータで許容回数を調整可能）
* `src/rules/kanji_open_close.rs`: 形式名詞・漢字の開きルール

### ③ 設定（ON/OFF・パラメータ調整）に強い `RuleRegistry`
`RuleRegistry::check_all(&ctx, Some(&settings))` のように設定マップを受け取ることで、特定のルールだけをOFFにしたり、パラメータを変更したルールを再登録したりすることが容易になりました。

単体テスト全19件がすべてパスし、高い保守性とパフォーマンスを両立しています。

## 4. エディタおよび校正パネルとの連動

今回のルール追加とリファクタリングにより、作家がエディタで文章を入力すると、以下のように機能します。

1. **エディタ上の波線表示**: 半角スペースや全角パイプが入力された瞬間に、Monaco Editor 上に警告の波線が表示されます。
2. **校正パネルでの一覧表示**: 「指摘一覧」タブに該当行・列番号とともに「全角空白への置換を推奨」「半角パイプを使用します」と表示されます。
3. **ワンクリック適用**: 「適用」ボタンを押すだけで、本文中の半角スペースが全角スペース（`　`）に、全角パイプが半角パイプ（`|`）に一発で安全に置き換わります。
