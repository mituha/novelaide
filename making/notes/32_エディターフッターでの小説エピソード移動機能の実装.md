# エディターフッターでの小説エピソード移動機能の実装

こんにちは！ 小説執筆用エディター **`novelaide`**（コードネーム: `novelaid-e`）の開発メイキング連載第32回です。

前回はエディター上部でのファイルタイトル表示と、その場でファイル名を直接書き換えられるインラインリネーム機能を実装しました。
今回はそれに続き、旧 Electron 版（`novelaid-editor`）で非常に好評だった「エディター最下部（フッター）での前・次エピソード移動（前後ナビゲーション）」を実装しました。

小説の連載や推敲では、「前の話はどういう引きで終わったっけ？」「この話を書いたらすぐ次の話に繋ぎたい」という場面が日常茶飯事です。
本機能により、ファイルツリーを何度も行ったり来たりすることなく、エディター下部のボタンをクリックするだけでスムーズに原稿を読み進め・書き進められるようになりました。

---

## 1. ユーザーからのリクエストと検討

今回の機能追加にあたり、ユーザーより以下のご要望をいただきました。

```text
/plan フッター部分の前及び次のエピソード移動についても実装を検討してください。なお、今回は移動時にタブを増やさない方向で検討してください
DocumentTypeとしてnovelのみの対応としてください
タブの位置についても維持する必要はありません。処理をシンプルに保つ事でバグの入り込む余地を減らすことを優先としてください。これにより、既に実装済みの処理の組み合わせのみで対処可能です
```

### 設計上の大きなポイント

1. **タブを増やさず「インプレイス（その場）」で切り替える**:
   - 通常の「ファイルを開く」動作だとクリックするたびにエディター上部のタブが増え、タブバーが原稿ファイルで溢れかえってしまいます。
   - 今回は**現在開いているタブを閉じてから新しい原稿を開く**ことで、タブ数を増やさずにすっきりと移動できる方式を採用しました。
2. **既存の検証済み API の組み合わせでシンプルに保つ**:
   - タブの挿入位置を維持しようとすると、内部のタブ配列を直接操作する低レベルなコードが必要になり、バグの温床になります。
   - そこで、ユーザーからの「処理をシンプルに保つ事でバグの入り込む余地を減らす」という助言を受け、既存の `await closeTab(activePath, paneId)` と `await openDocument(targetPath, { paneId, viewMode })` のシーケンス呼び出しを採用しました。
   - `closeTab` には未保存の変更がある場合の**自動保存機構**と**参照カウント管理**が既に安全に組み込まれているため、データの安全性が確実に担保されます。
3. **対象は小説原稿（`novel`）のみ**:
   - 資料やプロット、画像などにはナビゲーションを出さず、執筆対象である `documentType === 'novel'` の原稿のみを前後に遷移対象とします。

## 2. 実装のポイント

### 2.1. 同一フォルダ直下の兄弟原稿を自然順序ソート

前後のエピソードを特定するため、現在のファイルの親ディレクトリを取得し、同一フォルダ内のファイルを自然順序（Natural Sort）で整列します。

```typescript
// novel 形式のファイルのみを抽出し、数値を含む自然順序（昇順）でソート
const novelEntries = entries
  .filter((entry) => !entry.isDirectory && entry.documentType === 'novel')
  .sort((a, b) =>
    a.name.localeCompare(b.name, undefined, { numeric: true, sensitivity: 'base' })
  );

// 現在開いている原稿のインデックスを特定
const currentNorm = normalizePath(activePath);
const currentIndex = novelEntries.findIndex(
  (entry) => normalizePath(entry.path) === currentNorm
);

const prev = currentIndex > 0 ? novelEntries[currentIndex - 1] : null;
const next =
  currentIndex < novelEntries.length - 1 ? novelEntries[currentIndex + 1] : null;
```

一般的な文字列比較では `10_第9章.md` が `2_第1章.md` より前に来てしまうことがありますが、`numeric: true` を指定することで人間が期待する直感通りの章立て順序で並びます。

### 2.2. フッターナビゲーションUIの配置

`DocumentPane` の最下部に固定表示される `EpisodeNavigator` を配置しました。

* **左側**: 「◀ 前の話: [エピソード名]」ボタン
* **右側**: 「[エピソード名] : 次の話 ▶」ボタン
* **スタイル**: 目立ちすぎず執筆の邪魔にならないよう、通常時は控えめなトーン（`var(--text-muted)`）とし、マウスホバー時に鮮明にハイライトされます。

```mermaid
flowchart LR
    A["◀ 前の話: 01_プロローグ"] --> B["【現在の原稿】<br/>02_第1章_出会い"]
    B --> C["03_第2章_旅立ち : 次の話 ▶"]
```
