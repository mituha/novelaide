# 第37回：ファイル形式に応じたパネル動的構成と校正機能の最適化

こんにちは！ 小説執筆用エディター『**novelaide**』の開発チームです。

今回は、小説本文（`novel`）とメモ・プロット資料（`markdown`）、デザイン設定（`css`）など、多様なドキュメントをシームレスに扱うIDEならではの**「コンテキストに応じたパネル・アクティビティバーの動的構成」**の実装についてお届けします。

---

## 1. 課題：MarkdownやCSSで小説校正が動いてしまう？

前回のアップデートで、Linderaによる形態素解析のデバッグ機能や全頻出語の分析機能が揃い、小説の校正・文体解析は大幅に進化しました。

しかし、実際に原稿を執筆していると、小説本文（`.txt` など）の隣にプロット用のMarkdown（`.md`）や登場人物設定メモを並べて開く機会が多くあります。
この時、これまでのシステムでは以下の問題が発生していました：

1. **Markdown特有の記法が校正エラーと誤判定される**:
   - 見出し（`#`）の後の半角スペースが「半角空白禁止」に引っかかる。
   - 箇条書きやリンク構文が小説の作法違反として大量に検知されてしまう。
2. **アクティビティバーが不要なツールで煩雑化する**:
   - CSSや設定資料を開いている時にも「文章校正」パネルが表示され、操作のノイズになってしまう。
3. **しかしルビはMarkdownでも振りたい！**:
   - 一方で、プロット段階で「このキャラクターの読み仮名は……」とルビ（青空文庫形式 `|漢字《ルビ》`）を振る機能はMarkdownでも活用したい。

「**校正機能は小説（novel）編集時のみフル稼働させ、かつMarkdown編集時でもルビ振りは維持したい**」
そしてさらに一歩進めて、「**そもそもアクティビティバーのアイコン自体、そのファイル形式に関係ない時は隠れるようにできないか？**」という発想に至りました。

---

## 2. 設計：`PanelPlugin` への `supportedDocumentTypes` の導入

`novelaide` では、エディターのメイン画面を切り替えるビューシステム（`ViewRegistry`）において、すでに以下のように対応ファイル形式を宣言する仕組みを持っていました。

```typescript
// ビュープラグイン側の既存設計
export interface ViewPlugin {
  readonly supportedDocumentTypes: NovelaidDocumentType[];
  // ...
}
```

そこで今回、サイドパネルプラグイン（`PanelPlugin`）にもまったく同一の思想を導入し、**パネルごとにサポートするドキュメントタイプを宣言できる拡張**を行いました。

```typescript
export interface PanelPlugin {
  readonly id: string;
  readonly title: string;
  readonly icon: React.ComponentType<{ size?: number; className?: string }>;
  // ...
  /**
   * サポートするドキュメントタイプの配列。
   * 省略時（undefined）は、すべてのファイル形式で常にアクティビティバーに表示されます。
   */
  readonly supportedDocumentTypes?: NovelaidDocumentType[];
}
```

校正パネル（`CalibrationPanelPlugin`）には、以下のように設定します。

```typescript
export const CalibrationPanelPlugin: PanelPlugin = {
  id: 'novelaid.panel.calibration',
  title: '文章校正・文体解析',
  icon: SpellCheck,
  defaultPlacement: 'right',
  allowedPlacements: ['left', 'right'],
  scope: 'document',
  supportedDocumentTypes: ['novel'], // ★ novel の時のみサポート！
  // ...
};
```

## 3. 実装：アクティビティバーとサイドパネルの動的連動

この宣言をもとに、UIコンポーネント全体がスマートに連動する仕組みを構築しました。

### ① アクティビティバーでの動的アイコンフィルタリング
アクティビティバー（`ActivityBar.tsx`）は、現在開いているアクティブドキュメントの形式（`activeDocument.documentType`）を監視します。
`supportedDocumentTypes` が指定されているパネルは、現在の形式に合致しない場合、**アクティビティバーのボタン一覧から自動的に除外**されます。

```typescript
const panels = panelRegistry.getPanelsForSide(side).filter((p) => {
  if (p.supportedDocumentTypes && p.supportedDocumentTypes.length > 0) {
    if (!activeDocument) return false;
    if (!p.supportedDocumentTypes.includes(activeDocument.documentType)) {
      return false; // 非対応ならアイコンを表示しない
    }
  }
  return true;
});
```

### ② タブ切り替え時のパネル自動クローズ連動
小説本文で校正パネルを開いたまま、MarkdownやCSSのタブに切り替えた場合、非対応となったパネルが画面に残ってしまうと不自然です。
メインレイアウト（`MainLayout.tsx`）に監視フックを追加し、**非対応ファイルへの切り替えと同時にサイドパネルが自動的に閉じる**ようにしました。

```typescript
useEffect(() => {
  [leftActivePanelId, rightActivePanelId].forEach((panelId, idx) => {
    if (!panelId) return;
    const panel = panelRegistry.findPanel(panelId);
    if (panel?.supportedDocumentTypes && panel.supportedDocumentTypes.length > 0) {
      const isSupported = activeDocument && panel.supportedDocumentTypes.includes(activeDocument.documentType);
      if (!isSupported) {
        if (idx === 0) setLeftActivePanelId(null);
        else setRightActivePanelId(null);
      }
    }
  });
}, [activeDocument?.documentType, activeDocument?.path, leftActivePanelId, rightActivePanelId]);
```

### ③ エディター波線マーカーの安全破棄
エディター（`CodeEditor.tsx`）側でも、開いているファイルが `novel` 以外の場合は校正イベントを受信しても波線マーカー（`calibration`）を登録せず、常にクリアするようにガードを徹底しました。

### ④ Markdownでのルビ振り機能の維持
校正パネルと波線警告は無効化されますが、エディターのキーボードショートカット（<kbd>Ctrl+R</kbd> でルビ振り、<kbd>Ctrl+B</kbd> で傍点振り）および右クリックメニューのルビコマンドは、`novel` と `markdown` の両方でそのまま快適に利用できます。

## 4. 実際の動作イメージ

1. **小説ファイル（`.txt` 等）を開いている時**:
   - 右側アクティビティバーに「校正・解析」アイコンが出現。
   - クリックするとパネルが開き、作法指摘・文体統計・漢字比率ゲージなどがフル機能で動作。
2. **プロットや設定資料（`.md`）にタブを切り替えた時**:
   - **アクティビティバーから「校正・解析」アイコンがスッと消滅**。
   - 開いていた校正パネルも自動で閉じ、エディター上の波線マーカーも消去。
   - プロット内の単語を選んで <kbd>Ctrl+R</kbd> を押せば、普段通りルビダイアログが開いてルビを挿入可能。
3. **再び小説ファイルにタブを戻した時**:
   - アクティビティバーに「校正・解析」アイコンが即座に復帰！

エディターのドキュメントタイプとサイドパネル・アクティビティバーを連動させたことで、「いま自分が編集している文書に真に必要なツールだけが画面に並ぶ」という、非常にノイズの少ない洗練された執筆環境が実現しました。

この `supportedDocumentTypes` の仕組みは、今後新設される「Markdownプレビューパネル」や「AIキャラクターチャットパネル」などにもそのまま適用でき、拡張性も抜群です。
