## 1. なぜ Lindera（embed-ipadic）なのか？

従来の Electron 版（`novelaid-editor`）では、JavaScript 製の形態素解析エンジン `kuromoji` を使用していました。しかし、Tauri（Rust）環境において外部の Node.js ランタイムや巨大な辞書ファイル配布に頼ると、以下のような問題が生じます。

* **外部辞書ファイルの配置・探索トラブル**: OSごとのパス差異やインストーラーでのファイル欠損リスク。
* **メモリ消費と起動オーバーヘッド**: 重い辞書データを毎回展開することによるレスポンス低下。

これらを解決するために選定したのが **`lindera = { version = "6", features = ["embed-ipadic"] }`** です。
IPADIC 辞書データがバイナリ内に直接静的リンクされるため、**外部辞書ファイルが一切不要で、原理的にファイルパス問題や配布トラブルが起きません**。

## 2. 単体クレート先行テストで突き止めた「Lindera 6.x」の内部仕様

大型クレートをいきなり Tauri アプリ本体に結合すると、ビルド待ち時間が長くなりデバッグが極めて難しくなります。
そこで今回は、`tauri-plugin-novelaid-calibration` の独立した `Cargo.toml` の下で、まず単体テスト（`cargo test`）を先行実行しました。

このテスト駆動アプローチにより、ドキュメントだけでは見落としがちな Lindera 6.x の重要な仕様が事前に判明しました。

1. **文字列入力は `Cow<'a, str>`**:
   - `segmenter.segment()` はゼロコピー性能を最大化するため、単なる `&str` ではなく `std::borrow::Cow::Borrowed(text)` を要求します。
2. **トークン表層形は `token.surface`**:
   - 旧バージョンのサンプル等で見られる `token.text` ではなく、v6 では `surface` フィールドとなっています。
3. **詳細メタデータは `token.details()` メソッドによる遅延ロード**:
   - `token.details` フィールドは初期状態では `None` となっており、品詞や読みを取得するには `token.details()` メソッドを呼ぶことで辞書からオンデマンドに実データ（`Vec<&str>`）がロードされる仕様でした。

```rust
// 単体テストによる検証例
let dictionary = load_dictionary("embedded://ipadic")?;
let segmenter = Segmenter::new(Mode::Normal, dictionary, None);
let mut tokens = segmenter.segment(Cow::Borrowed("関西国際空港に行こう"))?;

assert_eq!(tokens[0].surface, "関西国際空港");
let details = tokens[0].details();
assert_eq!(details[6], "関西国際空港");           // 原形
assert_eq!(details[7], "カンサイコクサイクウコウ"); // 読み（カタカナ）
```

この単体テストがわずか **0.30秒** で通過することを確認した上で、プラグイン本体への組み込みへと進めました。

## 3. 実装した3大解析機能

`desktop.rs` に `Arc<RwLock<Segmenter>>` を組み込み、アプリ起動時に1度だけ辞書をロードしてシングルトン化することで、以下の3つの機能を高速に提供できるようになりました。

### ① 漢字からカタカナ読みをひらがな化する「ルビ候補自動抽出」
本文中の漢字を含む語句（2文字以上）を抽出し、Lindera が算出したカタカナ読みを、高速な文字コード演算（`c as u32 - 0x60`）でひらがなに変換します。
重複する語句を賢くフィルタリングした上で、エディタ上の行・列位置（`range`）とともにフロントエンドへ返却します。
作家はルビ支援タブから [挿入] ボタンを押すだけで、`｜関西国際空港《かんさいこくさいくうこう》` のような青空文庫形式をワンクリックで反映できます。

### ② 品詞を活用した「形式名詞・漢字の開き判定」
単なる文字列検索では、「事（名詞・一般）」と形式名詞・非自立名詞の「こと」の使い分けを誤検知してしまいます。
Lindera の品詞体系（`details[0] == "名詞"` かつ `details[1] == "非自立"` または `"形式名詞"`）を検証することで、**「〜すること」「〜なとき」「〜するもの」のように平仮名で開くべき箇所だけをピンポイントで検出**できるようになりました。

### ③ 自立名詞を正確に捉える「頻出語ランキング」
1文字の助詞や代名詞・数詞を除外し、物語の中で重要な意味を持つ自立名詞や固有名詞だけをリアルタイムに集計して出現回数順にソートします。特定の単語の多用やキャラクター名の出現頻度を一目で把握できます。

## 4. 今回のまとめと今後の展望

今回のステップにより、小説執筆エディター `novelaide` に強固で超高速な形態素解析の基盤が確立されました！

* **純 Rust 製エンジン Lindera 6.x の完全統合**:
  - IPADIC 内蔵により、外部辞書トラブルゼロの堅牢性を達成。
* **テスト駆動による安全な移行**:
  - 単体テストで API 仕様の癖を完全に解消してから本体に結合し、スムーズなビルド通過を実現。
* **作家の執筆を支える実践的な校正・ルビ基盤**:
  - ひらがなルビ自動生成、品詞連動の漢字開き、自立名詞頻出語ランキングが実稼働。

次のステップでは、この形態素トークン列を活用したさらなるルール拡張（ら抜き言葉の検出や助詞連続判定の精度向上）、および設定資料（登場人物名・造語）からユーザー辞書を動的生成する連携機能へと進めていきます！
