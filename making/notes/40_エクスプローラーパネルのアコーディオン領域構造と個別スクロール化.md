# 第40回：エクスプローラーパネルのアコーディオン領域構造と個別スクロール化

こんにちは！小説執筆用エディター **`novelaide`** 開発チームです。

`novelaide` のエクスプローラーパネルには、原稿ファイルツリーだけでなく、「開いているドキュメント」や「見出しアウトライン」など、執筆を強力にアシストするセクションが統合されています。

しかし、長編小説を執筆したり章立てが増えてファイルツリーが縦に長くなってくると、ひとつの深刻な問題が浮かび上がってきました。
今回は、**「ファイルが増えてもヘッダーが画面外に押し流されない」現代的IDE仕様のアコーディオン領域構造と個別スクロール化**、そしてセクション境界のリサイズ機能の実装についてお届けします！

---

## 1. 抱えていた課題：パネル全体がスクロールしてしまう！

これまでのエクスプローラーパネルでは、コンテナ要素に `overflow-y: auto` が指定されていました。
そのため、ファイルツリーの項目が増えたり展開フォルダが増加すると、**エクスプローラーパネル全体が1つの長い縦長ページのようにスクロール**してしまっていたのです。

```text
【これまでの挙動（パネル全体スクロール）】
┌──────────────────────────┐
│ [▼ 開いているドキュメント] │
│   ・01_プロローグ.md      │
│ [▼ 原稿ファイル]          │
│   ・01_プロローグ.md      │
│   ・02_第1章.md           │
│   ・03_第2章.md           │
│   ・...（何十件も続く）   │ ── ファイル一覧を下へスクロールすると……
│   ・50_エピローグ.md      │
│                          │
│ 画面外へ押し流されて見えない  │ ──「開いているドキュメント」や「見出しアウトライン」の
│ [▼ 見出しアウトライン]     │    ヘッダーごと上に消えてしまう！
└──────────────────────────┘
```

VS Codeなどのエディターを普段使っていると実感しますが、本来アコーディオンパネルというのは**「各セクションのヘッダーは常に定位置に存在し、スクロールするのはセクションの中身だけ」**であるべきです。

さらに、領域の使われ方についても改善の余地がありました。
セクションが1つだけ開いているときはそのセクションが画面下の空き領域を広々と使い切り、複数開いているときは均等・柔軟に按分されるのが理想です。

---

## 2. 領域配分とアコーディオン動作の設計

今回の改善にあたり、以下の領域ルールを設計しました。

### ① 開閉状態に応じたFlexbox自動按分
* **折りたたみ時（Collapsed）**:
  - `flex: 0 0 auto` でヘッダーの高さ（28px）のみを固定占有。
* **単一セクション展開時**:
  - `flex: 1 1 0` で、パネル内の残り領域をそのセクションが100%独占して画面下部まで広がる。
* **複数セクション展開時**:
  - 各セクションがウェイト値（初期比率 1:1:...）に応じて残り領域を按分。
* **全セクション折りたたみ時**:
  - 全ヘッダーが上部にコンパクトに整列し、下部に自然な余白ができる。

### ② 各セクション内部での個別スクロール
* パネルコンテナの `overflow-y: auto` を廃止し、`overflow: hidden; height: 100%;` に設定。
* 展開されたセクションのボディ（`.explorer-section-body.expanded`）に `flex: 1; min-height: 0; overflow-y: auto;` を設定。
* これにより、ファイルツリーや開いているドキュメント、アウトラインの内容がどれだけ長くなっても、**そのセクション枠の内側だけで独立してスクロールバーが表示される**ようになります。

### ③ セクション境界のドラッグリサイズ
* 展開されているセクション同士の境界線にドラッグハンドル（スプリッター）を配置。
* マウスドラッグで上下の高さを直感的に調整可能にし、最小高さ（48px）で押し潰しをガード。

## 3. 実装のポイント

### ① `ExplorerPanel.tsx` でのFlexウェイト＆ドラッグリサイズ管理

各セクションの高さウェイト（`weights`）をステートとして管理し、隣接する展開セクション間にリサイズハンドルを動的に配置しました。

```tsx
// ExplorerPanel.tsx
const handleResizeStart = useCallback(
  (e: React.MouseEvent, sectionAboveId: string, sectionBelowId: string) => {
    e.preventDefault();
    const elAbove = sectionRefs.current[sectionAboveId];
    const elBelow = sectionRefs.current[sectionBelowId];
    if (!elAbove || !elBelow) return;

    const rectAbove = elAbove.getBoundingClientRect();
    const rectBelow = elBelow.getBoundingClientRect();
    const totalWeight = (weights[sectionAboveId] ?? 1) + (weights[sectionBelowId] ?? 1);
    const startY = e.clientY;
    const totalH = rectAbove.height + rectBelow.height;

    const handleMouseMove = (moveEvent: MouseEvent) => {
      const deltaY = moveEvent.clientY - startY;
      const minHeight = 48; // セクションの最小高さ
      const clampedHeightAbove = Math.max(minHeight, Math.min(totalH - minHeight, rectAbove.height + deltaY));
      const clampedHeightBelow = totalH - clampedHeightAbove;

      setWeights((prev) => ({
        ...prev,
        [sectionAboveId]: (clampedHeightAbove / totalH) * totalWeight,
        [sectionBelowId]: (clampedHeightBelow / totalH) * totalWeight,
      }));
    };
    // ... mouseup 登録と解除
  },
  [weights]
);
```

### ② 子セクションへの確実な高さ伝播

各セクションの中身（`FileTreeSection` や `OutlineSection`）が内部のスクロールコンテナへ高さを正しく伝えるため、ラッパーコンポーネントに `height: 100%; display: flex; flex-direction: column; min-height: 0;` を設定しました。
また、「開いているドキュメント」セクションのリスト（`.open-docs-section-list`）にも `overflow-y: auto; flex: 1; min-height: 0;` を付与し、多数のファイルが開かれていてもセクション内で快適にスクロールするようにしました。

```css
/* ExplorerPanel.css */
.explorer-panel-container {
  display: flex;
  flex-direction: column;
  width: 100%;
  height: 100%;
  overflow: hidden; /* パネル全体のスクロールを遮断 */
}

.explorer-section-wrapper.expanded {
  min-height: 48px;
  overflow: hidden;
}

.explorer-section-body.expanded {
  flex: 1;
  min-height: 0;
  overflow-y: auto; /* 各セクション内部でのみスクロール */
  overflow-x: hidden;
  display: flex;
  flex-direction: column;
}

.explorer-section-resizer {
  height: 4px;
  margin-top: -2px;
  margin-bottom: -2px;
  position: relative;
  z-index: 10;
  cursor: row-resize;
  background-color: transparent;
  transition: background-color 0.15s ease;
}

.explorer-section-resizer:hover,
body.explorer-resizing .explorer-section-resizer {
  background-color: var(--accent-color, #3b82f6);
}
```

## 4. 他のパネルへの水平展開方針

エクスプローラーパネルでの領域按分・個別スクロールの使い勝手と安定性が実証されたことで、同様の複数セクションを持つ他のパネルにも同じ方針を展開するロードマップを定めました。

1. **検索パネル（SearchPanel）**:
   - 検索条件・置換入力セクションと、多数の検索マッチ結果一覧セクション。
2. **Git管理パネル（GitPanel）**:
   - ステージ済み変更、作業ツリー変更、コミット履歴セクション間の高さ按分と個別スクロール。
3. **メタデータパネル（MetadataPanel）**:
   - 登場人物一覧、地名一覧、プロット一覧セクションの独立スクロール。

サイドバー全体の一貫したUX向上に向けて、準備を整えています。

---

## 5. まとめ

今回の改修により、エクスプローラーパネルは以下のように生まれ変わりました。

1. **ファイルがどれだけ増えてもヘッダーが逃げない**: パネル全体のスクロールを廃止し、セクション枠内でのみスクロール。
2. **空き領域をスマートに活用**: 展開セクションが画面下部まで広がり、複数展開時は均等按分。
3. **マウスドラッグで自由自在にリサイズ**: 見出しアウトラインを広く見たい時や、ファイル一覧を広く見たい時など、シーンに合わせて瞬時にセクション高さを変更可能に。

長編の原稿整理や構成チェックが劇的にストレスフリーになりました！
