### 実施作業・設計判断
1. **【画像表示不可の根本原因調査】**:
   - `ImagePreview` において、`convertFileSrc(path)` を用いていたが、`src-tauri/tauri.conf.json` で `app.security.assetProtocol`（スコープ許可設定）が未定義であり、かつ `src-tauri/Cargo.toml` の `tauri` 依存関係で `protocol-asset` フィーチャーが有効化されていなかったため、WebView2 側で `asset://` プロトコルのアクセス権限が 403 / ブロックされ、画像の `alt` 属性テキストが表示されていた。
2. **【Tauri 2 Asset Protocol の完全有効化】**:
   - `src-tauri/tauri.conf.json`: `"security"` に `"assetProtocol": { "enable": true, "scope": ["**"] }` を設定。
   - `src-tauri/Cargo.toml`: `tauri = { version = "2", features = ["protocol-asset"] }` を設定。
3. **【二段構えのバイナリBlobフォールバック機構の新設】**:
   - Windows WebView2 やパス形式（日本語・特殊記号など）に起因するローカルプロトコル制限を完全に克服するため、Tauri プラグイン経由のバイナリ読み込みを追加。
   - `tauri-plugin-novelaid-fs/src/desktop.rs`: `read_file_binary(&self, path: &Path) -> Result<Vec<u8>>` を実装。
   - `tauri-plugin-novelaid-fs/src/commands.rs`: `read_file_binary` コマンドを追加。
   - `tauri-plugin-novelaid-fs/build.rs`: ACL コマンド一覧に `"read_file_binary"` を追加。
   - `tauri-plugin-novelaid-fs/permissions/default.toml`: `"allow-read-file-binary"` を追加。
   - `tauri-plugin-novelaid-fs/guest-js/index.ts`: `readFileBinary` API を公開。
   - `src/services/fileService.ts`: `readFileBinary(path)` メソッドを追加。
4. **【`ImagePreview.tsx` の表示堅牢化】**:
   - プライマリとしてネイティブな `convertFileSrc(path)` を使用。
   - `onError` 発生時、または初期解決失敗時に自動的に `fileService.readFileBinary(path)` を実行し、MIMEタイプ判定を行って `URL.createObjectURL(blob)` を生成・即座にフォールバック。
   - パス変更およびアンマウント時に `URL.revokeObjectURL` を呼び出して安全にメモリ解放。
   - 画像破損等で完全に読み込めない場合の専用エラー画面（警告アイコン、エラー説明、ファイル名表示）を追加。
5. **【仕様書・バージョン更新】**:
   - `docs/dev/DocumentTypeと各種ビューおよび画像プレビュー仕様.md`: Asset Protocol 有効化および二段構えBlobフォールバック仕様を追記。
   - バージョン更新: `0.45.1`（`npm version patch --no-git-tag-version`）。
