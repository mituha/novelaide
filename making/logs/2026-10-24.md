> これは、将来的なプラグイン化もですが、アプリ内での明確な役割を分担を表しています。
>
> まず、`novelaide`においても、同様に`tauri-plugin-novelaid-fs`として分ける構造への変更を検討してください。
> また、今後もプラグイン化可能な部分は極力分離する方向で計画を立ててください。
>
> 次に、各種定数、列挙型などの定義ですが、Rust側の定義からTypeScriptの定義を自動生成するようになっていたと思います。
> 同様に、自動生成される仕組みになっているかを確認してください。
> まった、この自動生成の構造について、仕様および記事を作成して記録しておいてください。


### 実施内容・作業手順
1. **`novelaid-editor-next/tauri-plugin-novelaid-fs` の構造調査と型自動生成の検証**
   - `ts-rs`（v12）の `#[derive(TS)]` と `#[ts(export, export_to = "../guest-js/models.ts")]` 属性の挙動を調査。
   - `cargo test` をトリガーとして `export_bindings_<name>` テスト関数が走り、TypeScript型定義（`guest-js/models.ts`）が出力される仕組みを実証。
2. **`novelaide/tauri-plugin-novelaid-fs` プラグインの構築と分離**
   - `tauri-plugin-novelaid-fs/` ディレクトリを作成。
   - `Cargo.toml`, `build.rs`, `permissions/default.toml` をセットアップ。
   - `src/` 配下に `lib.rs`, `commands.rs`, `desktop.rs`, `error.rs`, `models.rs`, `mobile.rs` を配置。
   - `package.json`, `tsconfig.json`, `rollup.config.js` を構成し、Rollup によるクライアントバンドル（`dist-js/`）を整備。
3. **Rust型からTypeScript型定義の自動生成テスト**
   - `cargo test --manifest-path tauri-plugin-novelaid-fs/Cargo.toml` を実行し、`guest-js/models.ts` が自動生成されることを確認。
   - `npm run build` により `dist-js/index.d.ts`, `dist-js/models.d.ts`, `dist-js/index.js`, `dist-js/index.cjs` の出力を確認。
4. **アプリ本体（`novelaide`）との統合と移行**
   - `src-tauri/Cargo.toml` に `tauri-plugin-novelaid-fs = { path = "../tauri-plugin-novelaid-fs" }` を追加。
   - `src-tauri/capabilities/default.json` に `"novelaid-fs:default"` パーミッションを追加。

   - `package.json` に `"tauri-plugin-novelaid-fs-api": "file:tauri-plugin-novelaid-fs"` および型同期用スクリプト `"typegen"` を追加。
   - `src/types/document.ts` および `src/services/fileService.ts` をプラグイン提供API＆型定義を利用するように全面リファクタリング。

### 設計上の判断理由
- **関心事の明確な分離（モジュラーモノリス）**:
  ファイルアクセスやYAMLフロントマター解析、非同期バックグラウンドスキャンといったOS/I/O寄りの高負荷処理をプラグインとして物理的に分離することで、フロントエンドUIとバックエンドロジックの責任境界を明確化。
- **`ts-rs` による二重管理（DRY原則違反）の完全撤廃**:
  手作業でのTypeScriptインターフェース定義をやめ、Rust側のEnum・Structを唯一の真実（Single Source of Truth）として自動生成パイプライン（`npm run typegen`）を構築。型定義の乖離による実行時バグを根本排除した。
- **今後のプラグイン分離方針の明文化**:
  Git履歴管理、AI連携、EPUB出力など、今後追加される重厚な機能もすべてプラグインとして順次分離可能にする拡張設計を確立。
