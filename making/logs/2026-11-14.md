### 調査・原因分析
1. **`Pending tool call not found` エラーおよび二重ツール呼び出し受信の発生要因**:
   - `DocumentContext.tsx` 内で `externalControlService.initMcpListener()` を実行する際、開発環境（Vite / React StrictMode）におけるマウント・アンマウント・再マウントのタイミングで、非同期の `await listenToolCalls(...)` が完了する前に `destroy()` が走ると `this.unlistenMcp` が `null` のままとなり、2回目のマウントで新たなリスナーが重複登録されていた。
   - その結果、単一の `mcp://tool-call` イベントに対して2つのリスナーが同時に発火。1回目のハンドラーが `respondToolCall`（`pending_calls.remove`）を完了させた後、2回目のハンドラーが同一 `callId` で再度 `respondToolCall` を呼び出したため、Rust バックエンド側で `Pending tool call not found: <call_id>` エラーが発生していた。
2. **`get_project_structure` などのツール名不整合**:
   - `tauri-plugin-novelaid-mcp/src/server.rs` および `guest-js/domain/tools.ts` の公式ツール定義で公開されている `get_project_structure` や `get_active_document` に対し、フロントエンド側ディスパッチャー `externalControlService.executeTool` の `switch` 分岐が不足していた。

### 修正内容
1. **フロントエンド側の重複初期化・重複実行防止ガード (`externalControlService.ts`)**:
   - `initMcpListener()` に `initPromise` キャッシュを導入し、非同期初期化中の多重呼び出しを完全に統合。
   - `handledCallIds` セット（直近200件）を導入し、同一 `callId` のツール呼び出し要求が万一重複して届いた場合でも2回目の実行を自動スキップ。
2. **Rust バックエンド側の応答耐障害性向上 (`server.rs`)**:
   - `respond_tool_call` において、`pending_calls.remove(&payload.call_id)` が `None` であっても（すでに解決済みまたはタイムアウト済み）、致命的エラー（`Err`）とせず警告ログ出力にとどめ `Ok(())` を返すよう改善。
3. **客観的エラー抑止 (`guest-js/index.ts`)**:
   - `respondToolCall` 呼び出しに `.catch(...)` ハンドラを付与し、未補足例外（`Uncaught (in promise)`）の発生を完全抑止。
4. **不足ツールの追加実装 (`externalControlService.ts`)**:
   - `get_project_structure`: `list_files` / `get_open_documents` とともにプロジェクト構造・開いているタブ情報を返却。
   - `get_active_document`: アクティブな原稿（または開いているドキュメント）の最新未保存バッファ・文字数・タイトル・パスを返却。
