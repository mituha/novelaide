# メタデータおよびインデックス自動生成仕様

## 1. 概要と背景

小説プロジェクトの大規模化に伴い、章やエピソード、設定資料（登場人物・舞台・プロット）が複数のフォルダに階層化されていきます。
これらのフォルダごとに目次やカタログの役割を果たす `index.md` を手動でメンテナンスすることは執筆者にとって負担となるため、各ファイルの YAML Frontmatter メタデータをもとに `index.md` を自動生成・同期する機能が計画されています。

> [!IMPORTANT]
> **共通仕様・自動生成規約の参照元**:
> - 純粋なファイルフォーマット規約およびコア項目定義: [Frontmatterメタデータ共通仕様](../../novelaid-editor-docs/docs/dev/Frontmatterメタデータ仕様.md)
> - インデックス自動生成共通規約: [インデックス自動生成共通仕様](../../novelaid-editor-docs/docs/dev/インデックス自動生成共通仕様.md)

本仕様は、共通仕様に基づき、**`novelaide`** におけるコアメタデータ（`type`, `title`, `description`）の入出力制御および将来のエディター自動生成コマンドの実装方針を定義するものである。

> [!NOTE]
> **OKF（Open Knowledge Format）との関係について**:
> 本機能の設計思想は OKF のコンセプト（ファイル自身が自己記述的なメタデータを持ち、フォルダ単位の index で構造化される）と共通していますが、現段階で直接 OKF 仕様に準拠・拘束されるものではありません。小説執筆の利便性とシンプルな Markdown 構造を最優先とし、必要最小限のコアメタデータ仕様を規定します。

## 2. コアメタデータ仕様

`index.md` の自動生成において中核となるメタデータフィールドは以下の3点です。

| フィールド名 | 型 | 入力形式 | 必須性 | 主な用途・役割 |
| :--- | :--- | :--- | :--- | :--- |
| **`title`** | `string` | 1行テキスト | 任意（推奨） | ドキュメントの正式名称や話数タイトル。`index.md` でのリンクテキスト（`[タイトル](./filename.md)`）や見出し名として使用。未指定時はファイル名から自動フォールバック。 |
| **`type`** | `string` | 1行テキスト（候補提示あり） | 任意 | ドキュメントの種別・分類。`index.md` 生成時の抽出フィルタリングやグルーピングに使用。未入力時は Frontmatter にキーを出力しない（既存・自由記述互換）。 |
| **`description`** | `string` | 1行テキスト | 任意 | ドキュメントの要約・1行説明。`index.md` の一覧リストにおける補足文（箇条書きの説明文やテーブル行の概要列）として使用。一覧性を維持するため1行に制限。 |

### 2.1 `type` の運用方針

- **オプショナル・自由入力型**:
  - `type` は必須入力ではありません。値が未入力または空文字の場合、Frontmatter に `type` キーは出力されません。
  - 入力補助として HTML `<datalist>` による代表的プリセット（サジェスト）を提示しますが、ユーザーが独自の分類名（例: `spell`, `organization`, `side-story` 等）を自由に入力可能です。
- **代表的なプリセット値**:
  - `chapter`: 本編章・エピソード
  - `character`: 登場人物・設定シート
  - `location`: 地名・施設・舞台設定
  - `plot`: プロット・構成案・タイムライン
  - `index`: 目次・インデックス
  - `memo`: 執筆メモ・アイデア出し

### 2.2 `description` の1行入力化と他キーの共存

- **1行テキスト化の理由**:
  - `index.md` 自動生成時の Markdown テーブル行やリストアイテム（`- [Title](path) : Description`）としてのレイアウト崩れを防ぎ、機械的な抽出・整形を容易にするため、`MetadataPanel` 上の入力を 1 行（`<input type="text">`）に統一しました。
- **任意キー（`summary` 等）との非破壊共存**:
  - システムが既存ファイル内の `summary` やその他のユーザー独自 Frontmatter を勝手に削除・変換・統合することはありません。
  - Frontmatter の自由拡張領域はそのまま保持され、`MetadataPanel` 上では「カスタムフィールド」として透過的に確認・編集が可能です。

### 2.3 空キーのクリーンアップ仕様

`MetadataPanel` 上で入力値を空（全削除）にした場合、Frontmatter 内部に `title: ""` や `type: ""`、`tags: []` などの空キーを残さず、オブジェクトからキー自体を削除して保存します。これにより YAML Frontmatter を常に清潔な状態に維持します。

## 3. 将来的な `index.md` 自動生成の出力イメージ

### パターン A: リスト形式（シンプルな目次）

```markdown
# 登場人物一覧

- [神代 玲央](./chara_reo.md) - 本作の主人公。記憶を失った元錬金術師。
- [セラフィーナ](./chara_sera.md) - 神聖王国の第二王女。玲央を保護する。
- [バルガス](./chara_vargas.md) - 王立騎士団長。玲央の能力を警戒している。
```

### パターン B: テーブル形式（カタログ形式）

```markdown
# 第1章 エピソード一覧

| 話数・タイトル | 種別 | 概要 |
| :--- | :--- | :--- |
| [第1話 目覚めの森](./ep01.md) | chapter | 名もなき森で記憶を失った青年が目を覚ます。 |
| [第2話 出会いと剣](./ep02.md) | chapter | 王女セラフィーナの一行と遭遇し、魔獣の襲来を退ける。 |
| [第3話 王都への道](./ep03.md) | chapter | 保護される形で王都へ向けた護衛旅が始まる。 |
```

## 4. フロントエンド実装構成

- **編集コンポーネント**: `src/components/Metadata/MetadataPanel.tsx`
  - `title`: 1行 input (`metadata.title`)
  - `type`: 1行 input (`metadata.type`, `list="meta-type-presets"`)
  - `description`: 1行 input (`metadata.description`)
  - `tags`: カンマ区切り配列変換
  - `FolderTree` アイコンによる視覚的強調
