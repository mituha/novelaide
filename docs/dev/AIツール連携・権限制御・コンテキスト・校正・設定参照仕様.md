# AIツール連携・権限制御・コンテキスト・校正・設定参照仕様

## 1. 概要と基本方針

本仕様書は、小説執筆用エディター `novelaide` における AI エージェント機能（Pi SDK）のツール連携、原稿保護のためのツール権限制御、DocumentState経由の安全な読み書き統一パイプライン、コンテキスト管理（プッシュ型 vs プル型）、フォルダーアクセス制限（スコープ境界）、およびAI校正・設定参照（RAG）の全体仕様を定義するものです。

### 設計の5大原則
1. **DocumentState 経由の読み書き統一（Single Source of Truth）**:
   - ディスク（ファイルシステム）への直接読み書きを完全に排除し、未保存バッファの競合消失、画面非同期、Undo消失を防止する。
2. **Pi SDK 標準ツール（`read`, `write`, `edit`）との完全互換・置換**:
   - `novelaid-cli` や LLM の事前学習と整合させ、Tauri環境の安全なアダプターとして提供する。
3. **書き込み系と読み取り系の権限分離**:
   - 原稿破壊を防ぐため、デフォルトは書き込みを禁止した「安全・読み取り専用（`Read-only`）」とし、用途に応じて「純粋対話（`Off`）」「直接編集（`Edit`）」を選択可能とする。
4. **フォルダー階層アクセス制限（スコープ境界ガード）**:
   - ツリー状にシリーズや巻が配置されている執筆プロジェクトにおいて、他巻のネタバレ混入や誤書き換えを遮断する。
5. **コンテキストの二重化（プッシュ型 vs プル型）**:
   - 目の前の原稿をピンポイントで扱う「入力欄簡易チップ（全文注入）」と、プロジェクト設定をAIが自律取得する「目次案内（ツール参照）」を分離し、トークン消費を最適化する。

## 2. Pi SDK 標準ツールの互換・置換設計

### 2.1 ツール定義とスキーマ

`novelaid-cli`（CLIエージェント）および Pi Coding Agent SDK 標準のツール命名・引数スキーマをそのまま採用し、Tauri デスクトップ環境向けの安全なアダプターとして置換（Polyfill）します。

| ツール名 | パラメータ | 動作内容 | 権限分類 |
|---|---|---|---|
| `read` | `path: string`<br/>`offset?: number`<br/>`limit?: number` | 指定ドキュメントの内容を取得（未保存バッファ優先） | 読み取り系（安全） |
| `write` | `path: string`<br/>`content: string` | 新規ドキュメント作成・全テキスト更新 | **書き込み系（変更）** |
| `edit` | `path: string`<br/>`edits: Array<{ oldText: string, newText: string }>` | 指定ドキュメントの差分テキスト置換 | **書き込み系（変更）** |
| `search_metadata` | `query: string` | 設定資料（Frontmatter / YAML / Markdown）のキーワード検索 | 読み取り系（安全） |
| `scan_proofread` | `text?: string` | 誤字脱字、文末重複（「〜た。」連続）、ら抜き言葉の高速スキャン | 読み取り系（安全） |
| `extract_ruby` | `text?: string` | 難読漢字・固有名詞のルビ候補抽出（`\|親文字《ルビ》` 形式） | 読み取り系（安全） |
| `get_open_documents` | なし | 開かれているドキュメント（タブ）一覧と未保存状態の取得 | 読み取り系（安全） |
| `get_active_document` | `side?: 'left' \| 'right'` | フォーカスされているペインの最新バッファ取得 | 読み取り系（安全） |

> **注意**: シェルコマンドを実行する `bash` ツールは、デスクトップエディターのセキュリティ保護および小説執筆の主目的から除外・ブロックします。

## 3. DocumentState 経由の安全な読み書き統一パイプライン

### 3.1 ディスク直接処理の禁止理由
ディスク（ファイルシステム）へ直接書き込みまたは直接読み取りを行った場合、以下の致命的な破綻が発生します：
1. **未保存バッファの競合消失**: エディター上でユーザーが未保存の執筆を行っている最中にAIがディスクを直接上書きすると、ユーザーの次回保存（`Ctrl+S`）でAIの変更がすべて消失する。
2. **画面への非同期**: ディスクを更新してもエディター画面に即座に反映されず、ユーザーが書き換えに気付けない。
3. **Undo / Redo の喪失**: エディターの編集履歴（Undoスタック）に乗らないため、AIの変更を `Ctrl+Z` で取り消せない。
4. **未保存原稿の読み取り漏れ**: ディスクから読むと、ユーザーが今まさに書き進めた最新テキストがAIに伝わらない。

### 3.2 統一処理フロー（Single Source of Truth）

```
[ AI Agent: read / write / edit ]
           │
           ▼
[ ChatView: ToolExecutor ]
   ├── ① 権限・スコープ境界チェック（アクセス許可確認）
   │
   ├── ② DocumentContext (openDocuments) の確認
   │     ├─ [既に開いている場合]:
   │     │    └─ DocumentState.content を参照 / updateContent で即時更新
   │     │
   │     └─ [未オープンの場合]:
   │          ├─ openDocument(path) を実行（内部的にロード＆タブ展開）
   │          └─ DocumentState.content を参照 / updateContent で即時更新
   │
   ▼
[ エディターUI（左右ペイン） ]
   ├─ 画面上のテキストが即座に同期更新
   ├─ isDirty = true（未保存インジケーター表示）
   └─ ユーザーが目で確認、Undo（Ctrl+Z）、保存（Ctrl+S）、または破棄が可能
```

## 4. ツール権限レベル（Tools Permission Mode）

小説執筆における用途と安全性に応じ、以下の3段階の権限レベルを提供します。

| モード名 | 許可ツール | 禁止ツール | 利用シーン・効果 |
|---|---|---|---|
| **Off**<br/>（純粋対話） | なし（`tools: []`） | すべて | 執筆の雑談、アイデア出し。小規模モデル（2B〜7B）でツール定義によるトークン圧迫や誤動作をゼロにし、最速のレスポンスを得る。 |
| **Read-only**<br/>（安全・読み取り専用）<br/>※デフォルト | `read`<br/>`get_open_documents`<br/>`get_active_document`<br/>`search_metadata`<br/>`scan_proofread`<br/>`extract_ruby` | `write`<br/>`edit` | **「原稿を勝手に書き換えられたくないが、AIに章や設定を読ませて感想・改善案・誤字指摘をもらいたい」** という執筆者の最も標準的な用途。原稿破壊リスクゼロ。 |
| **Edit**<br/>（執筆・直接編集許可） | 上記すべて ＋<br/>`write`<br/>`edit` | なし | AIに誤字脱字の修正を直接エディター原稿へ反映させたり、ルビ振り、新規プロットファイルの自動生成を任せたい上級者向け。 |

### UI表現
- チャット入力ヘッダーまたはパラメータ領域に以下を配置：
  1. **ツール有効（ON / OFF）スイッチ**: OFF で即座に「純粋対話（`Off`）」モードへ移行。
  2. **「ファイル直接変更を許可（Write Access）」チェックボックス**（ツールON時のみ有効）:
     - OFF（デフォルト）: **Read-only モード**
     - ON: **Edit モード**
- チャットメタデータ（`.ch` の `metadata.parameters.toolsPermission`）に保存・永続化。

## 5. フォルダー階層アクセス制限（スコープ境界ガード）

小説プロジェクトの典型的なツリー構造：
```text
MySeriesProject/
├── 00_settings/          <-- 設定資料（キャラ、世界観、用語集）
├── 10_plot/              <-- 全体プロット、構想
└── 20_novels/            <-- 原稿フォルダー
    ├── 第1巻/
    │   ├── 01_第1章.txt
    │   └── 02_第2章.txt
    └── 第2巻/            <-- 未公開の巻（第1巻の相談で見せたくない）
        ├── 01_第1章.txt
        └── 02_第2章.txt
```

### 5.1 スコープ制限の目的
1. **他巻のネタバレ防止**: 第1巻の推敲中に、第2巻以降のプロットや原稿をAIが読み込んでネタバレを含めてしまう事故の防止。
2. **同名ファイルの混同防止**: 各巻の「第1章.txt」の取り違え防止。
3. **原稿の誤書き換え遮断**: 他巻の原稿を誤って上書き・差分編集（`write` / `edit`）するリスクの完全遮断。

### 5.2 安全境界ルール（デフォルト）
`toolExecutor` 実行時に対象パスを検証：
- **許可パス**:
  1. 現在アクティブな原稿と同一のフォルダー（例: `20_novels/第1巻/` 配下）
  2. 設定・構想資料フォルダー（`00_settings/`, `10_plot/`, `wiki/` 等）
- **遮断パス**:
  - 他の巻のフォルダー（例: `20_novels/第2巻/`）
  - プロジェクトルート外（パストラバーサル）
  - 遮断時は `Access Denied: Path outside allowed scope` エラーをAIに返却。

## 6. コンテキスト選択の二重アプローチ（プッシュ型 vs プル型）

| 方式 | UI配置と動作 | 最適な利用シーン |
|---|---|---|
| **① プッシュ型<br/>（全文注入）** | **入力欄近くの簡易チップ**<br/>例: `[✓] 第1話.txt (4,200文字)`<br/>ワンクリックで「全文を含める/含めない」を切替。左右ペインの切替にも対応。 | **「今書いているこの章を校正して」「このセリフを直して」** という、目の前の原稿に集中したピンポイント作業。初速が最速。 |
| **② プル型<br/>（自律ツール参照）** | **スコープ目次案内**<br/>AIシステムプロンプトに「アクセス可能な設定ファイルおよび原稿のパス一覧」を目次としてコンパクトに案内。 | **「魔法の詠唱ルールって何だっけ？」「主人公の年齢設定を確認して」** という設定・世界観の確認。AIが自律的に `read` や `search_metadata` を呼んで取得。 |

## 7. 実装分と将来案の区分

### 7.1 今回実装フェーズ（フェーズ 1〜3）
1. **【フェーズ 1】DocumentState経由のPi SDK互換ツール基盤・権限レベル・スコープガード**:
   - `read`, `write`, `edit` 互換ツール
   - `toolsPermission: 'none' | 'read' | 'write'`
   - `DocumentContext` 経由のメモリ内バッファ統一更新（未オープン時自動タブ展開）
   - フォルダー・スコープ境界ガード
   - 設定検索ツール（`search_metadata`）の接続
2. **【フェーズ 2】入力欄の簡易コンテキスト選択UI（全文注入チップ）と目次案内**:
   - 入力欄近くのアクティブ原稿チップ（文字数表示＋全文注入ON/OFF）
   - システムプロンプトへのアクセス可能ファイル目次案内
3. **【フェーズ 3】小説執筆特化支援・AI校正の再統合とクイックアクション**:
   - 誤字脱字、文体リズム、編集者講評、ルビ提案のクイックアクションバー
   - AIの提案した差分修正（`edit`）のエディター直接反映

### 7.2 将来案（仕様策定のみ、将来フェーズで検討）
1. **ファイルエクスプローラー型 RAGスコープ設定UI**:
   - プロジェクトツリーからAIのアクセス対象フォルダーをチェックボックスで個別に視覚指定できるGUI。
2. **ローカル埋め込み型ベクトル検索（Vector RAG）**:
   - 長編小説の「類似シーン」「感情曲線」意味検索エンジン（ONNX Runtime等のローカルモデル活用）。
3. **時系列ネタバレ防止メタデータガード**:
   - 原稿やプロットの時系列タグ（第何話以前）に基づく自動参照制限。
